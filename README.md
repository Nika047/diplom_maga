# Прогноз положения малоразмерного БПЛА по отметкам РЛС: IMM + нейросеть

Код выпускной квалификационной работы (магистратура ГУАП) «Разработка программы
прогнозирования положения воздушного объекта при помощи алгоритмов экстраполяции на
основе нейронной сети».

**Задача.** По отметкам обзорной РЛС (дальность, азимут, угол места раз в 2 с)
спрогнозировать положение малоразмерного самолётного БПЛА на 2-10 с вперёд (1-5
обзоров). Главная трудность - маневры: классические фильтры запаздывают на входе в
разворот.

**Подход.** Многомодельный фильтр IMM (модели постоянной скорости CV и
координированного разворота CT) даёт базовый прогноз, нейросеть-корректор по окну
из 20 последних обзоров поправляет его. Сравниваются корректоры LSTM, GRU,
Transformer и Mamba, сквозные сети без IMM, а также разные схемы встраивания сети в
фильтр.

## Основные результаты (версия 1, архив)

> Идёт **версия 2** проекта: все этапы переписаны на общем ядре и пересчитываются с нуля в четырёх прогонах
> (`base` / `merged` x синтетика x1 / x4) и трёх случаях доплера (без доплера, по траектории, по телеметрии) с
> отбором гипотез и доверительными интервалами по полётам. Числа ниже - версия 1 (результаты в
> [`home_results_archive/v1/`](home_results_archive/v1/)); числа версии 2 появятся после домашних запусков в
> `home_results/<прогон>/`.

ADE - средняя ошибка прогноза по горизонтали на горизонтах 2-10 с, м; сети -
среднее по 3 seed. Подробно - [`.agent_docs/THESIS_NOTES.md`](.agent_docs/THESIS_NOTES.md),
глава 4.

| Метод | Реальные полёты (test) | Объединённый test (реальные + сгенерированные) |
|---|---|---|
| Линейная экстраполяция | 85,3 | 84,9 |
| Фильтр Калмана | 62,1 | 67,2 |
| IMM, подобранный генетическим алгоритмом | 44,1 | 49,5 |
| IMM + GRU (этап 4) | 40,3 (-9%) | 41,1 (-17%) |
| IMM + GRU, обучение с расширением реальных полётов (этап 9) | 38,8 (-12%) | 40,6 (-18%) |
| **IMM с доплером + GRU, обучение с расширением (итоговая модель, этап 12)** | **37,8 (-14%)** | **36,6 (-26%)** |

В скобках - изменение к подобранному IMM без доплера. Итоговая модель требует РЛС,
измеряющую радиальную скорость; в работе она моделируется по GPS-истине. «Реальные полёты» - вариант данных `base`,
«объединённый test» - вариант `merged` (ниже, «Данные»).

- Четыре архитектуры корректора статистически неразличимы (в пределах 0,6 м, порядок
  на разных наборах разный). Корректор итоговой модели - GRU: на `merged` она
  лучшая на val и одна из самых быстрых.
- Сеть после фильтра (поправка к прогнозу IMM) работает лучше, чем сеть внутри
  фильтра (по типу KalmanNet) и чем сеть без фильтра.
- На траекториях из генератора выигрыш сети к IMM в 2-3 раза больше, чем на
  реальных полётах: проверка на данных генератора обучения завышает пользу сети.
- Начало маневра по-прежнему не видно заранее: на входе в разворот выигрыш
  меньше всего.
- Шум отметок РЛС - около половины ошибки гибрида: почти без шума переобученный
  IMM + GRU ошибается на 20 м вместо 40 на реальных полётах (этап 10). Чем точнее
  РЛС, тем больше выигрыш сети к IMM, но сеть надо обучать под точность конкретной
  РЛС.
- Оракул (прогноз по точному состоянию цели, этап 11): на реальных полётах ошибка
  гибрида - примерно 49% шум РЛС, 42% непредсказуемость движения и только 9% сам
  метод. На входе в маневр непредсказуемость - 58%: начало разворота по прошлому
  не видно даже при точном состоянии.
- Доплер (радиальная скорость, этап 12) ускоряет распознавание маневра и снижает
  ошибку на входе в разворот на 7-19%; на объединённом test гибрид с доплером -
  36,5 м против 49,5 у IMM без доплера (-26%). На реальных полётах выигрыш меньше,
  вероятно, из-за того, что доплер в работе моделируется по GPS-истине.
- Вес ошибкам на входе в маневр при обучении (этап 13) - размен, а не улучшение:
  вход точнее на 7-18%, но средняя ошибка растёт на 7-31% за счёт прямой.
- Три варианта прогноза («прямо / влево / вправо» с вероятностями, этап 14) вместе
  покрывают будущее на 18-30% лучше одного прогноза, но выбрать верный заранее
  нельзя: на входе в маневр класс угадывается лишь в четверти случаев. Это веер
  возможных положений для строба и отображения, а не замена прогнозу.
- Ансамбль обученных сетей (этап 15) даёт ещё 1-4% без обучения: на реальных
  полётах 38,2 м (3 seed, обучение с расширением). Разброс сетей ансамбля
  предупреждает о больших ошибках: там, где они расходятся, ошибка в 2,5-3 раза
  больше.
- Модульная схема (распознаватель поворота и два корректора-эксперта, этап 16)
  почти не лучше одного корректора (-0..-2%, на уровне ансамбля из трёх сетей).
  С идеальным распознавателем она дала бы -6..-11%, но начало поворота по прошлым
  отметкам не видно: на входе в маневр распознаватель прав лишь в трети случаев.
- Доплер складывается с другими приёмами (этап 17): ансамбль сетей с доплером -
  ещё -2..-3% (на реальных полётах 36,6 м, -17% к IMM), строб при том же покрытии
  меньше на 13-20%, при пропусках отметок преимущество доплера сохраняется.
  Больше синтетики помогает только на сгенерированных траекториях.

Числа обновляются по мере экспериментов; текущее состояние -
[`.agent_docs/PROJECT_STATE.md`](.agent_docs/PROJECT_STATE.md).

## Данные

- **Реальные полёты:** `flight_logs/` - 150 логов телеметрии самолётных БПЛА
  (CSV, GPS). Очищаются, режутся на непрерывные куски, переводятся в местную
  систему ENU и размечаются на участки: прямая, вход в маневр, маневр, выход.
  Выборки делятся целыми логами.
- **Синтетика:** кинематический генератор маневрирующих траекторий
  (`data/generator.py`), откалиброванный по совокупной статистике логов train.
- **Модель РЛС** (`radar/model.py`): отметки с гауссовым шумом в полярных
  координатах, положение РЛС своё для каждой трассы, пропуски обнаружения.
- **Четыре прогона** (переменные окружения `DIPLOM_DATA` = `base` / `merged` и `DIPLOM_SYNTH` = `1` / `4`):
  - `base` - test только из реальных полётов, синтетика только в обучении;
  - `merged` - сгенерированные траектории тоже делятся на train / val / test;
  - `DIPLOM_SYNTH` - во сколько раз больше сгенерированных траекторий (x4: в `base` больше только обучение, в
    `merged` больше весь пул, и val / test тоже другие).

  У каждого прогона свои каталоги результатов, кэша, весов и хранилища обученных моделей.
- **Расширение реальных полётов в обучении:** переразметка РЛС (другое положение и шум), зеркальное отражение,
  растяжение по скорости x0,85 и x1,15; val и test не расширяются.
- **Три случая доплера:** без доплера; доплер, где истинная скорость берётся по GPS-траектории; доплер, где истинная
  скорость - скорость GPS-приёмника из лога (телеметрия).

Входы моделей - только то, что доступно в реальной работе: отметки РЛС и
производные от них величины (оценки IMM, вероятности моделей, невязки). Тип
аппарата и телеметрия во входы не подаются.

## Установка

Python 3.13, Windows (проверено на Windows 10 и 11).

```powershell
python -m venv .venv
.venv\Scripts\pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128   # с GPU
# без GPU: --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\pip install -r requirements.txt
```

## Запуск

Работа идёт по этапам: один этап - один скрипт `run_stageN.py` (0-11), каждый пишет сводку проверок PASS / FAIL в
`results/<прогон>/stageN/<случай>/summary.txt`, рисунки - рядом, журнал - в `log/<прогон>/`. Любой запуск можно
остановить и продолжить той же командой: обученные сети лежат в `model_store/<прогон>/`, попытки подбора - в базе
Optuna, прерванное обучение продолжается с последней эпохи.

```powershell
.venv\Scripts\python.exe run_all.py --data base --synth 1      # все этапы подряд для прогона (затем merged x1, x4)
.venv\Scripts\python.exe run_all.py --data base --synth 1 --smoke   # проверка конвейера на малой выборке (без GPU)
.venv\Scripts\python.exe export_results.py --run base_x1       # сводки, метрики и PNG прогона -> home_results/
```

Обучение (этапы 2-9) рассчитано на GPU; без GPU скрипты запускаются только с `--smoke`.

| Этап | Скрипт | Что делает |
|---|---|---|
| 0 | `run_stage0.py` | Логи, разметка участков, генератор, разбиение, расширение реальных полётов, проверки доплера |
| 1 | `run_stage1.py` | Линейная экстраполяция, фильтр Калмана, IMM: генетический подбор в каждом случае доплера |
| 2 | `run_stage2.py` | Корректоры LSTM / GRU / Transformer / Mamba и сети без IMM: подбор по точности и времени отклика |
| 3 | `run_stage3.py` | Длина окна, размер сети, объём данных |
| 4 | `run_stage4.py` | Эволюционный поиск архитектуры корректора |
| 5 | `run_stage5.py` | Схемы встраивания сети в фильтр (A, Б1-Б5); выбор основы |
| 6 | `run_stage6.py` | Гипотезы по одной против основы: вес ошибкам на входе в маневр, три гипотезы, начало маневра, модульная схема; отбор |
| 7 | `run_stage7.py` | Сочетания выживших гипотез; итоговая модель случая |
| 8 | `run_stage8.py` | Ансамбли: жадный отбор по val, время отклика, разброс как неопределённость |
| 9 | `run_stage9.py` | Пропуски отметок, строб, шум РЛС и оракул, точность доплера, сгенерированный test, реакция на маневр |
| 10 | `run_stage10.py` | Доверительные интервалы бутстрепом по полётам, сравнение случаев |
| 11 | `run_stage11.py`, `predict.py` | Пакеты итоговых моделей и программа прогноза по логу или по отметкам РЛС |

Скрипты версии 1 (этапы 0-19) - в `archive_v1/` (запуск версии 1 - из коммита `d880403`).

## Структура

| Каталог | Содержимое |
|---|---|
| `data/` | Чтение логов, разметка, генератор, разбиение, окна для сетей, расширение данных |
| `radar/` | Модель измерений РЛС |
| `filters/` | Модели движения, IMM, фильтр Калмана, линейная экстраполяция |
| `models/` | Корректоры GRU, LSTM, Transformer, Mamba; гибридные схемы |
| `training/`, `tuning/` | Обучение, генетический подбор, поиск архитектуры |
| `eval/`, `viz/` | Единые метрики, сводки, рисунки |
| `pipeline/` | Общее ядро этапов версии 2: пути и состояние, данные и окна по случаям доплера, оценка, реестр, отбор, гипотезы |
| `home_results/` | Сводки, метрики и все рисунки полных запусков на GPU (`<прогон>/`); `home_results_archive/v1/` - версия 1 |
| `.agent_docs/` | Подробная документация: план, архитектура, платформа, заметки для текста |

Все параметры - в `config.py`. Случайные процессы - от одного seed (`RANDOM_SEED`),
поэтому этапы воспроизводимы. Каталоги `results/`, `cache/`, `artifacts/`, `log/`, `model_store/`
создаются запуском и в репозитории не хранятся.
