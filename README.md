# Прогноз положения малоразмерного БПЛА по отметкам РЛС: IMM + нейросеть

Код выпускной квалификационной работы (магистратура ГУАП) «Разработка программы
прогнозирования положения воздушного объекта при помощи алгоритмов экстраполяции на
основе нейронной сети».

**Задача.** По отметкам обзорной РЛС (дальность, азимут, угол места раз в 2 с)
спрогнозировать положение малоразмерного самолётного БПЛА на 2-10 с вперёд (1-5
обзоров). Главная трудность - маневры: классические фильтры запаздывают на входе в
разворот.

**Подход.** Многомодельный фильтр IMM (модели постоянной скорости CV и
координированного разворота CT) даёт базовый прогноз, нейросеть-корректор по окну
из 20 последних обзоров поправляет его. Сравниваются корректоры LSTM, GRU,
Transformer и Mamba, сквозные сети без IMM, а также разные схемы встраивания сети в
фильтр.

## Основные результаты

ADE - средняя ошибка прогноза по горизонтали на горизонтах 2-10 с, м; сети -
среднее по 3 seed. Подробно - [`.agent_docs/THESIS_NOTES.md`](.agent_docs/THESIS_NOTES.md),
глава 4.

| Метод | Реальные полёты (test) | Объединённый test (реальные + сгенерированные) |
|---|---|---|
| Линейная экстраполяция | 85,3 | 84,9 |
| Фильтр Калмана | 62,1 | 67,2 |
| IMM, подобранный генетическим алгоритмом | 44,1 | 49,5 |
| IMM + GRU (итоговая модель) | 40,3 (-9%) | 41,1 (-17%) |
| IMM + GRU, обучение с расширением реальных полётов (этап 9) | 38,8 (-12%) | 40,6 (-18%) |

В скобках - изменение к подобранному IMM. «Реальные полёты» - вариант данных `base`,
«объединённый test» - вариант `merged` (ниже, «Данные»).

- Четыре архитектуры корректора статистически неразличимы (в пределах 0,6 м, порядок
  на разных наборах разный). Итоговая модель - IMM + GRU: на `merged` она лучшая на
  val и одна из самых быстрых.
- Сеть после фильтра (поправка к прогнозу IMM) работает лучше, чем сеть внутри
  фильтра (по типу KalmanNet) и чем сеть без фильтра.
- На траекториях из генератора выигрыш сети к IMM в 2-3 раза больше, чем на
  реальных полётах: проверка на данных генератора обучения завышает пользу сети.
- Начало маневра по-прежнему не видно заранее: на входе в разворот выигрыш
  меньше всего.
- Шум отметок РЛС - около половины ошибки гибрида: почти без шума переобученный
  IMM + GRU ошибается на 20 м вместо 40 на реальных полётах (этап 10). Чем точнее
  РЛС, тем больше выигрыш сети к IMM, но сеть надо обучать под точность конкретной
  РЛС.
- Оракул (прогноз по точному состоянию цели, этап 11): на реальных полётах ошибка
  гибрида - примерно 49% шум РЛС, 42% непредсказуемость движения и только 9% сам
  метод. На входе в маневр непредсказуемость - 58%: начало разворота по прошлому
  не видно даже при точном состоянии.
- Доплер (радиальная скорость, этап 12) ускоряет распознавание маневра и снижает
  ошибку на входе в разворот на 7-19%; на объединённом test гибрид с доплером -
  36,5 м против 49,5 у IMM без доплера (-26%). На реальных полётах выигрыш меньше,
  вероятно, из-за того, что доплер в работе моделируется по GPS-истине.
- Вес ошибкам на входе в маневр при обучении (этап 13) - размен, а не улучшение:
  вход точнее на 7-18%, но средняя ошибка растёт на 7-31% за счёт прямой.

Числа обновляются по мере экспериментов; текущее состояние -
[`.agent_docs/PROJECT_STATE.md`](.agent_docs/PROJECT_STATE.md).

## Данные

- **Реальные полёты:** `flight_logs/` - 150 логов телеметрии самолётных БПЛА
  (CSV, GPS). Очищаются, режутся на непрерывные куски, переводятся в местную
  систему ENU и размечаются на участки: прямая, вход в маневр, маневр, выход.
  Выборки делятся целыми логами.
- **Синтетика:** кинематический генератор маневрирующих траекторий
  (`data/generator.py`), откалиброванный по совокупной статистике логов train.
- **Модель РЛС** (`radar/model.py`): отметки с гауссовым шумом в полярных
  координатах, положение РЛС своё для каждой трассы, пропуски обнаружения.
- **Два варианта данных** (переменная окружения `DIPLOM_DATA`):
  - `base` - test только из реальных полётов, синтетика только в обучении;
  - `merged` - сгенерированные траектории тоже делятся на train / val / test.

  У каждого варианта свои каталоги результатов, кэша и весов.

Входы моделей - только то, что доступно в реальной работе: отметки РЛС и
производные от них величины (оценки IMM, вероятности моделей, невязки). Тип
аппарата и телеметрия во входы не подаются.

## Установка

Python 3.13, Windows (проверено на Windows 10 и 11).

```powershell
python -m venv .venv
.venv\Scripts\pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128   # с GPU
# без GPU: --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\pip install -r requirements.txt
```

## Запуск

Работа идёт по этапам: один этап - один скрипт `run_stageN.py`, каждый пишет
сводку проверок PASS / FAIL в `results/stageN/summary.txt`, рисунки - рядом,
журнал - в `log/`.

```powershell
.venv\Scripts\python.exe run_stage0.py            # данные: очистка, разметка, генератор, разбиение
.venv\Scripts\python.exe run_stage4.py --smoke    # быстрая проверка конвейера на малой выборке
.venv\Scripts\python.exe run_all.py --data merged # все этапы подряд для варианта данных
```

Обучение (этапы 2-6, 8-10) рассчитано на GPU; без GPU скрипты запускаются только с
`--smoke`. `run_all.py` пропускает этапы, у которых уже есть сводка.

| Этап | Скрипт | Что делает |
|---|---|---|
| 0 | `run_stage0.py` | Логи, разметка участков, генератор, разбиение |
| 1 | `run_stage1.py` | Модель РЛС, линейная экстраполяция, фильтр Калмана, IMM |
| 2 | `run_stage2.py` | Корректор GRU после IMM |
| 3 | `run_stage3.py`, `run_stage3_window.py` | LSTM, GRU, Transformer, Mamba, сети без IMM; длина окна |
| 4 | `run_stage4.py`, `run_stage4_baselines.py` | Генетический подбор параметров IMM и сетей, итог на test |
| 4б | `run_stage4b.py` | Эволюционный поиск архитектуры корректора |
| 4в, 4г | `run_stage4c.py`, `run_stage4d.py` | Размер сети и объём синтетики |
| 5 | `run_stage5.py` | Прогноз начала маневра |
| 6а | `run_stage6a.py` | Пропуски отметок |
| 6б | `run_stage6b.py` | Строб - область, где окажется цель |
| 6в, 6г | `run_stage6c.py`, `run_stage6d.py` | Схемы встраивания сети в фильтр |
| 7 | `predict.py` | Программа прогноза по логу или по отметкам РЛС, отчёт с картой |
| 8 | `run_stage8.py` | Проверка на отдельном сгенерированном test |
| 9 | `run_stage9.py` | Расширение реальных полётов в обучении |
| 10 | `run_stage10.py` | Вклад шума отметок РЛС |
| 11 | `run_stage11.py` | Оракул: прогноз по точному состоянию цели, разложение ошибки |
| 12 | `run_stage12.py` | Доплер: радиальная скорость в фильтре и в сети |
| 13 | `run_stage13.py` | Вес ошибкам на входе в маневр при обучении |

## Структура

| Каталог | Содержимое |
|---|---|
| `data/` | Чтение логов, разметка, генератор, разбиение, окна для сетей, расширение данных |
| `radar/` | Модель измерений РЛС |
| `filters/` | Модели движения, IMM, фильтр Калмана, линейная экстраполяция |
| `models/` | Корректоры GRU, LSTM, Transformer, Mamba; гибридные схемы |
| `training/`, `tuning/` | Обучение, генетический подбор, поиск архитектуры |
| `eval/`, `viz/` | Единые метрики, сводки, рисунки |
| `home_results/` | Сводки и рисунки полных запусков на GPU (base и merged) |
| `.agent_docs/` | Подробная документация: план, архитектура, платформа, заметки для текста |

Все параметры - в `config.py`. Случайные процессы - от одного seed (`RANDOM_SEED`),
поэтому этапы воспроизводимы. Каталоги `results/`, `cache/`, `artifacts/`, `log/`
создаются запуском и в репозитории не хранятся.
