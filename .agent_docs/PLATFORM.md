## Варианты данных и прогоны

Версия 2 (решение пользователя 26-27.10.2026): прогон = вариант данных x объём синтетики. Две
переменные окружения, имя прогона `config.RUN_NAME`:

| Переменная | Значения | Смысл |
|---|---|---|
| `DIPLOM_DATA` | `base` (по умолчанию), `merged` | `base`: синтетика только в train, val и test - только реальные полёты, Z-84 - holdout. `merged`: сгенерированные траектории делятся на train / val / test (70/15/15 по сценариям) и добавляются к реальным, Z-84 в общих данных, holdout нет |
| `DIPLOM_SYNTH` | `1` (по умолчанию), `4` | во сколько раз больше сгенерированных траекторий (`SYNTH_FACTOR`). В `base` больше только train; в `merged` больше весь пул, поэтому val и test тоже другие и больше |

Порядок прогонов: `base_x1`, `merged_x1`, затем (если хватит времени) `base_x4`, `merged_x4`.
Код написан под все четыре сразу.

Каталоги у прогона свои, запуск одного не меняет другой (`config.py`):

| Что | Путь | В git |
|---|---|---|
| журналы | `log/<прогон>/` | нет |
| результаты | `results/<прогон>/stageN/<случай>/` | нет (в репозиторий - `home_results/<прогон>/`) |
| кэш (окна, Optuna) | `cache/<прогон>/` | нет |
| веса этапов | `artifacts/<прогон>/` | нет |
| **хранилище обученных моделей** | `model_store/<прогон>/<этап>/<случай>/<подпись>_s<seed>/` | нет; **не удалять** |

**Хранилище моделей** (`training/store.py`): модель = `model.pt` (веса, нормализатор, настройки)
+ `meta.json` (история обучения, проверки; пишется последним - признак готовности). Повторный
запуск готовую модель не обучает, а загружает (`run_experiment(store=..., store_key=(этап,
случай))`): прогнозы и проверки воспроизводятся без повторного обучения. Прерванное обучение
продолжается с последней эпохи по `ckpt.pt` (`train(..., ckpt_path=...)`); на CPU продолжение
совпадает с непрерывным обучением, на GPU - нет (состояние CUDA не хранится). Попытки подбора -
в базе Optuna в `cache/<прогон>/`. Смоук пишет в `model_store/<прогон>/_smoke/`.

**Случаи доплера** (`common/cases.py`): `nodop`, `dop_traj`, `dop_tele`; `use_case(случай,
net_input, sigma_vr)` временно ставит флаги `DOPPLER_*` и возвращает прежние.

Архив версии 1: перед первым запуском версии 2 папки `results*/`, `cache*/`, `artifacts*/`, `log*/`
(старая раскладка без `<прогон>`) переносятся в `archive_v1/`; ничего не удаляется.

В merged val и test смешанные (в test 4,3 ч реальных полётов и 13,1 ч
сгенерированных), поэтому сводки этапов дополнительно содержат разделы «ADE по

**Прогон** (порядок: `base_x1`, `merged_x1`; затем, если хватит времени, `base_x4`, `merged_x4`). Запуск в фоне, обрыв
ssh его не останавливает (журнал - `run_all_<прогон>.out` и `log\<прогон>\`):

```powershell
$P = (Get-Location).Path
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = "cmd /c `"cd /d $P && .venv\Scripts\python.exe -u run_all.py --data base --synth 1 >> run_all_base_x1.out 2>&1`"" }
```

**Двойной запуск невозможен:** `run_all.py` и каждый этап берут замок (`cache\<прогон>\.run_all.lock`, `state\.lock_<этап>_<случай>`); второй запуск того же прогона завершается сообщением `[отказ]`. Замок снимается сам при остановке процесса. Перед запуском проверьте, нет ли уже работающего (`Get-CimInstance Win32_Process ...`, ниже).

**Прогоны запускать по очереди и не нагружать ПК другими задачами:** время отклика сети - цель подбора и метрика сравнения, оно
измеряется, а не считается; при загруженном процессоре или видеокарте замер искажается (в смоуке на рабочем ПК при
параллельном расчёте первая попытка показала 306 мс вместо 0,2).

То же для остальных прогонов: `--data merged --synth 1`, `--data base --synth 4`, `--data merged --synth 4` (и
имя файла `run_all_<прогон>.out`). Каталоги прогонов раздельные, но параллельный запуск искажает замеры времени.

**Остановка и продолжение.** Остановить (прерванное обучение сети сохранило последнюю эпоху, прерванный подбор -
завершённые попытки):

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'run_all\.py|run_stage\d+\.py' } | ForEach-Object { taskkill /F /T /PID $_.ProcessId }
```

Продолжить - **та же команда запуска**: `run_all.py` пропускает этапы со сводками, внутри этапа готовые сети берутся из
`model_store\<прогон>\`, подбор продолжается из `cache\<прогон>\<этап>\<случай>\optuna.db`, оборванное
обучение сети - с последней сохранённой эпохи (на GPU продолжение не совпадает с непрерывным до бита). Теряется
не больше одной эпохи и одной попытки подбора. Ход: `Get-Content run_all_base_x1.out -Wait -Tail 20 -Encoding UTF8`.

**Отдельный этап или случай** (например, после правки кода):

```powershell
.venv\Scripts\python.exe -u run_stage2.py --case nodop        # DIPLOM_DATA / DIPLOM_SYNTH - переменные окружения
.venv\Scripts\python.exe -u run_all.py --data base --synth 1 --from run_stage5.py --force   # заново с этапа 5 и дальше (готовые сети берутся из хранилища)
.venv\Scripts\python.exe -u run_all.py --data base --synth 1 --case nodop           # только один случай доплера
```

(для отдельного скрипта прогон задают `$env:DIPLOM_DATA='merged'; $env:DIPLOM_SYNTH='1'`; в `cmd`-запуске фоном
`set DIPLOM_DATA=merged&& ...` без пробела перед `&&`).
